# 文章翻訳の検証

## v0.1.4で比較した訳文

Google翻訳のWeb画面とtranslationhubに同じ検体を貼り、決算・論文・日常の文章で、意味、文脈、自然さ、意図を比較した。モデル選定に使った12件と、選定後に別途固定した6件を分けている。採点はAIによるもので、読者は原文、各方式の実訳、採点理由を同じ画面で照合できる。[公開比較レポート](https://translationhub.waxyghost64.chatgpt.site/quality/index.html) · [検証データ](../dist/quality/results.json) · [測定方法](../dist/quality/METHOD.txt)

次の例は実装を改善する過程で使用した。独立した6件の点数には含めていない。

| 試したこと | 実機での結果 |
| --- | --- |
| 直前の段落を参照して同じ英文の語義を選ぶ | PLaMoで `The crane stayed where it was.` を湿地の鳥の描写に続けると「鶴」、建設機械の描写に続けると「クレーン」になった。 |
| 短い日英対訳を次の段落の文脈に渡す | 眼鏡を受ける代名詞が `it` から `them` に、屋台のくじを二枚引く動作が `rolled two cards` から `drew two tickets` に変わった。別の眼鏡の例では単数のままだった。「結構です」の承諾と辞退も依然として取り違える。 |
| 金額と比率を照合する | Chromeで「125億円」だけの入力も英語になった。ブラウザー版PLaMoで `JPY 12.5 billion` は「125億円」、「0.6パーセントポイント、0.6%ではない」の区別も保持できた。 |
| 哲学の引用をOCRの改行を残して貼る | ブラウザー版とOllama版のPLaMoで段落を維持し、冒頭の「虚偽ではなく無意味」という区別を訳せた。括弧内の比較では程度の違いが消え、複数段落にまたがる引用には閉じ括弧が一つ余った。引用全体を一度に訳す別試験でも程度の違いは復元できなかった。 |

ブラウザー版PLaMoは初回の取得と照合の後、Chromeを終了・再起動し、モデル配布元への通信を遮断しても翻訳できた。操作の中止と再開、表、数量、コード表記も検証した。ブラウザーで動くTranslateGemma 4Bも試したが、決算の見通しを引き上げなかった文の意味が反転し、モデル取得後のオフライン再起動にも失敗した。このリリースでのTranslateGemmaの選択肢は端末のOllamaを使う。

比較対象のGoogle訳はGoogle翻訳Webの画面に表示された実訳。任意接続のGoogle Cloud Translation LLMは、送信同意・リクエスト・障害時の処理とGoogle実サーバーの認証エラー応答を確認した。有効な有料キーでの訳文は今回の比較に含めていない。

## v0.1.2の検証

v0.1.2では、WindowsのChromeから同じ文章を入力し、表示された訳を原文と照合した。決算・技術文は検証用の合成文で、金額・符号・単位・否定・表の行列を採点対象にした。

| 原文の意味 | 修正中に再現した問題 | 修正後に実機で確認した結果 |
| --- | --- | --- |
| 120 Hzで測った遅延は2.5 ms | 軽量ローカルの日英訳で7.5 msになった | 120 Hzと2.5 msの両方を保持 |
| 0.05 mAでしきい値に達しなかった。識別子は `FINAL_V2` | Chromeで `Ma` と `final_v2` に変化した | 単位の大小文字と識別子を保持 |
| タブ区切りの決算表に `(12.40)` と `+8.75` がある | Chromeで項目と金額が一続きの文になった | 元の列に同じ表記で残った。Markdown表の罫線、空セル、指数表記も回帰検証に含めた |
| 設備投資額は `¥12.5 billion` | TranslateGemma 4Bが「12.5億円」と訳した | PLaMoとTranslateGemmaの両方で `¥12,500,000,000` を保持。記号から通貨の国を推定していない |
| 売上高は7.5%減、利益率は0.6パーセントポイント改善 | 段落全体の再翻訳で、7.5%が減少の起点として訳された。別の訳では percentage points と % が混同された | 両モデルで7.5%の減少と「0.6パーセントポイント（0.6%ではない）」を保持 |
| 測定装置を30項目列挙したあとに、出荷を承認しなかった理由が続く | 軽量ローカルが出力上限まで同じ語を繰り返し、後半が欠けても成功としていた | 英日では各項目の温度と末尾の否定を確認。日英で節を分けても測定値を落とした例は、部分訳を完成として保存する前に停止した |

数値の照合が通っても、語義や事実関係を完全に判定できるわけではない。今回の日英訳ではTranslateGemmaが「通期見通しを**引き上げなかった**」を “did not **revise** its full-year outlook” と訳し、下方修正の可能性まで消していた。軽量モデルでも、キャッシュフローのマイナス1億2,000万ドルと前年のプラス8,000万ドルを保ちながら、単に前年と比較した文に「大差ない」という評価を付け足した例があった。

## 検証範囲

- Chrome内蔵翻訳、軽量ローカル（英日FuguMT・日英OPUS-MT）、Ollama上のPLaMo 3 Translate 0.8B Q4_K_MとTranslateGemma 4Bは実モデルで確認した。
- Google CloudとApps Scriptはローカルの模擬サーバーで、送信同意、言語、文字列、エラー、長文の中止を確認した。クラウドの実訳・利用枠は今回の測定対象外。
- 書き出し・読み込み、途中で中止して再開、エンジン設定で実モデルを変更した場合の混在防止も検証した。保存するモデル情報はプロバイダーと設定上のモデル名。同じタグの重みを端末で入れ替えた場合の識別には対応していない。

## 回帰テスト

`npm test` はNode.jsとPythonの標準テストランナーで前処理、データ復元、ローカル推論、接続経路を検証する。利用者のキーや外部翻訳サービスは使わない。

`npm ci` 後の `npm run test:browser` はインストール済みのデスクトップChromeと一時ローカルサーバーを起動し、原文入力から訳文表示までを実行する。既定はChrome内蔵翻訳。`TRANSLATIONHUB_ENGINE=wasm` で軽量ローカル、`TRANSLATIONHUB_ENGINE=plamo-web` でブラウザー版PLaMoを同じ検体で試せる。初回はモデル取得の通信が発生する。`TRANSLATIONHUB_QA_URL` でテスト先を指定し、`TRANSLATIONHUB_QA_REPORT` で合成文と実訳をJSONに書き出せる。

`TRANSLATIONHUB_QA_CORPUS=published` を追加すると、公開レポートの18件を実際の翻訳画面で再実行する。書き出したJSONには新しく表示された訳文、完走状況、空の段落、所要時間が残る。公開済みの訳文・採点は新しい実測値に転記しない。
